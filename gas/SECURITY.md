# 議事録づくり（Apps Script 版）の安全面について

情報システムの担当者向けに、このツールが扱うデータ・使う権限・置き場所・残るリスクをまとめます。版は 0.1.0（開発中）です。

## しくみの概要

- Google スプレッドシートに入れた Apps Script が、**使う人本人の権限（OAuth）で**動きます。全員の分を読めるサービスアカウントや管理用のアカウントは使いません。本人が開けない会議メモや議事録は読めません
- 会議メモの中身を Gemini に送り、議事録の下書きを受け取ります。Gemini は文章を返すだけで、ファイルの作成や登録はしません
- 人が確認画面で承認したときだけ、確定版の議事録を保存先フォルダに作り、Backlog の課題とカレンダーの予定を登録します

## データの置き場所と、見られる人

| データ | 置き場所 | 見られる人 |
|---|---|---|
| 会議メモ（Gemini によるメモ） | 主催者のドライブ（このツールは読むだけ） | 共有された人 |
| 下書き（非公開情報・要確認事項の一覧入り） | 本人のマイドライブの「下書き」フォルダ | 本人だけ。承認かやめるでゴミ箱へ |
| 議事録（確定版） | 保存先フォルダ（本番は共有ドライブ） | フォルダのメンバー |
| 会議・TODO の一覧、使った記録 | 本人の管理スプレッドシート | 本人だけ（共有しない決まり） |
| 会議の中身 | Gemini（本番は Vertex AI） | 下の「Gemini に送るデータ」を参照 |
| TODO の件名・会議名・開催日・元メモと議事録のリンク | Backlog（いまの Claude 版と同じ） | プロジェクトのメンバー |
| 期限のリマインド | 本人の Google カレンダー（非公開の予定） | 本人と、招待した社内の人 |
| Backlog・Gemini（AI Studio）の API キー | 本人のユーザー プロパティ | 本人だけ。シート・ログ・エラーの表示には出さない |

実行ログ（Apps Script の実行記録）には、会議 ID と件数と、エラーのときのエラーの説明だけを書きます。会議の中身や TODO の内容は書きません。

## 権限

`src/appsscript.json` で使う権限を決めています。ドライブ全体を書き換えられる権限（`drive`）やカレンダー全体の権限（`calendar`）は使いません。

| 権限 | 使い道 |
|---|---|
| `drive.readonly` | 会議メモを探して読む。保存先フォルダから前回の議事録を探して読む。保存先フォルダの共有の範囲を確かめる |
| `drive.file` | このツールが作ったファイル・フォルダ（下書き・確定版・最初の設定で作るフォルダ）だけを作る・書き出す・ゴミ箱に移す |
| `documents.readonly` | 会議メモをタブ（メモ・文字起こし）ごとに読む |
| `calendar.events` | 期限のリマインドを作る。同じ予定がすでにないか確かめる |
| `spreadsheets.currentonly` | この管理スプレッドシートだけを読み書きする |
| `script.container.ui` | メニューと画面を出す |
| `script.external_request` | Backlog の API と Gemini の API を呼ぶ |
| `script.scriptapp` | 自動で下書きを作る設定（15 分ごとの実行）をオン・オフする |
| `script.send_mail` | 自動で下書きを作ったときに、本人あてに知らせる |
| `userinfo.email` | 本人のアドレスを知る（招待から本人を外す・承認した人を記録する） |
| `cloud-platform`（本番だけ足す） | Vertex AI を呼ぶ。実際にできることは、会社が付けた役割（Vertex AI ユーザー）の範囲だけ |

## Gemini に送るデータ

会議メモの本文（メモと文字起こし）、前回の議事録、前回の TODO の課題キー・件名・状態を送ります。

| 呼び方 | 学習に使われるか | Google 側に残るか | このツールでの扱い |
|---|---|---|---|
| AI Studio の無料のキー | **使われることがある** | 残る | 開発用。**架空のサンプルしか送れない**ようにしてある |
| AI Studio の有料のキー | 使われない | 不正利用の監視のため一定期間残る。残さない設定ははっきり用意されていない | 使わない |
| Vertex AI（会社の Google Cloud） | 使われない | **設定で残さないようにできる**（ゼロデータ保持） | 本番で使う |

本番の Vertex AI では、次の 3 つでゼロデータ保持にします。保持の期間や申請のしかたは変わることがあるので、設定するときに Google Cloud の最新の資料（[Vertex AI とゼロデータ保持](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/data-governance)）で確かめてください。

1. 一時的なキャッシュを止める
2. 不正利用の監視のための記録を残さないよう申請する（Google Cloud の契約によっては、最初から対象外）
3. 送った内容と返事を記録する機能（リクエストとレスポンスのログ）をオフのままにする

処理する場所は、設定シートの「Vertex AI の場所」で東京（`asia-northeast1`）にします。新しいモデルは、最初は東京で使えずグローバル（`global`）だけのことがあります。

## 機密性・完全性・可用性の対策

### 機密性

- 本人の権限で動き、本人が開けないものは読めない
- 下書きは本人だけのフォルダに置き、承認してから確認用のメモを消した確定版だけを保存先に置く
- 保存先フォルダが社外のアドレス・ドメインや「リンクを知っている全員」に共有されていたら、承認できない（確認画面と承認の直前の 2 回確かめる）
- カレンダーの招待は、設定シートの「社内のドメイン」のアドレスだけ。予定は非公開で作る
- 自動で作るのは、決めた会議名のメモだけ（人事面談などを AI に送らないため）。初期値はオフ
- API キーは本人のユーザー プロパティに置き、エラーの表示からも消す

### 完全性

- AI は文章を返すだけ。登録するのは、人が承認した管理シートの内容だけ。登録先も、設定した Backlog のプロジェクトと本人のカレンダーに限る（会議メモに AI への指示がまぎれ込んでも、勝手には登録されない）
- AI の返事は決まった形（JSON）で受け取り、日付・区分の形を確かめてから使う
- 承認は同時に 1 つしか動かない（鍵をかける）。登録した課題キーを 1 件ごとにシートに書き、やり直したときは登録済みを飛ばす。課題の登録は、サーバーのエラーで自動的にやり直さない（二重登録を防ぐため）
- 確定版の最後に、AI が下書きしたこと・承認した人と日時・元メモのリンク・版を入れる。あとからの変更はドライブの版の履歴に残る

### 可用性

- 議事録の保存先は、本番では共有ドライブ（会社の持ち物）にする。辞めた人のマイドライブと一緒に消えないようにするため
- Google・Gemini・Backlog の一時的なエラーは、時間をおいて自動で数回やり直す。それでもだめなら「エラー」にして、メニューからやり直せる
- 承認が途中で止まっても、続きから登録できる
- Gemini のモデル名は設定で変えられる
- このツールが使えなくなっても、元の会議メモは残るので、Claude 版か手作業に切り替えられる

## 設計で消せずに残るリスク

- **Backlog の API キーは、その人が Backlog でできることを全部できる**（Backlog の仕組み）。漏れたらすぐ作り直す。将来は Backlog の OAuth に変えられる
- **管理スプレッドシートを人と共有すると、編集できる人がプログラムを書き換え、持ち主の権限で動かせてしまう**。試用の間は共有しない決まりにし、全社では使う人がコードを触れない社内限定のアドオンで配る
- **会議の中身を AI に送ること自体は避けられない**。送ってよい会議かどうかは、使う人が選ぶ（自動のときは会議名で絞る）
- **AI の書いた内容は間違うことがある**。承認は人が行い、その記録が議事録とシートに残る

## 会社で用意してもらうもの（本番）

1. Google Cloud プロジェクト 1 つ（情報システムの担当者が管理）。Vertex AI を使えるようにし、上のゼロデータ保持を設定する。使う人の Google グループに「Vertex AI ユーザー」の役割を付ける。予算のアラートを付ける
2. 共有ドライブの議事録フォルダ（メンバーは社内の人だけ）
3. Google Workspace の管理者による、社内アプリとしての許可（全社では社内限定のアドオンとして配る）
