# 議事録づくり（Apps Script 版）

Google Meet の「Gemini によるメモ」から議事録を作り、社内の TODO を Backlog の課題と Google カレンダーのリマインドに登録します。いまの Claude 版（`skills/meeting-tasks`）と同じことを、**パソコンに何も入れず、Google の中だけで**行います。

> **開発中（0.1.0）です。** いまは開発用の設定で動かす段階です。本物の会議メモは使わず、架空のサンプルの会議メモだけで試してください。

- 設計の考え方：[設計図](https://claude.ai/artifact/77Q96D9pK68Sq1TxDE9ueF)（いまは作った人だけが開けます）
- 扱うデータ・権限・残るリスク：[SECURITY.md](SECURITY.md)

## できること

1. 管理シートのメニューから会議メモを選ぶと、Gemini が議事録の下書きを書く（書き方はいまの版の `minutes-template.md` と同じ）
2. 下書きは**本人だけのフォルダ**に作る。文章は下書きのドキュメントで、TODO の担当者・期限・登録先は管理シートの「TODO」で直す
3. メニュー「確認して承認する」で、いまの版と同じ 1 枚の確認画面を出す。「承認する」を押すと、次をまとめて行う
   - 確定版の議事録を保存先フォルダに作る（確認用のメモを消し、残った要確認事項は「決まっていないこと」へ。最後に、誰がいつ承認したかを入れる）。下書きはゴミ箱へ
   - 社内の TODO を Backlog に登録する
   - 期限を Google カレンダーに入れる（終日・非公開・前日 9:00 に通知。招待は社内のアドレスだけ）
4. 前回の議事録（保存先フォルダの同じ会議名のもの）と比べて、「前回からの変更」を書く

## 使い方

| やること | メニュー |
|---|---|
| 会議メモから下書きを作る | 「議事録」→「議事録を作る…」 |
| 架空のサンプルで試す | 「議事録」→「サンプルの会議メモで試す」 |
| 確認して承認する | 「議事録」→「確認して承認する…」（承認を待っている会議が複数あるときは、「会議」シートでその行を選んでから） |
| 使った記録を集計する（テスト用） | 「議事録」→「使った記録を集計する」 |

確認画面で「やめる」を押すと、何も登録せずに下書きをゴミ箱へ移します。承認が途中で止まったときは、原因を直してからもう一度承認すると、続きから登録します（登録済みの課題はもう一度登録しません）。

## 開発用に自分の環境で動かす

自分の Google アカウントだけで動かせます。会社の準備（Google Cloud・共有ドライブ）は要りません。

### 1. スプレッドシートとプログラムを用意する

1. Google ドライブで、新しいスプレッドシートを作る（名前の例：`議事録づくり（開発）`）。**人と共有しない**
2. 「拡張機能」→「Apps Script」を開く
3. `gas/src/` のファイルを入れる。どちらかの方法で入れる
   - **clasp を使う（おすすめ）**：ターミナルで `npm install -g @google/clasp` → `clasp login`。Apps Script の「プロジェクトの設定」にあるスクリプト ID を、`gas/.clasp.json.example` をコピーした `gas/.clasp.json` に書き、`gas` フォルダで `clasp push` を実行する
   - **手で貼る**：Apps Script の「プロジェクトの設定」で「appsscript.json マニフェスト ファイルをエディタで表示する」をオンにする。`gas/src/` の各ファイルと同じ名前のファイルを作り、中身を貼る（`.gs` はスクリプト、`.html` は HTML。`Prompt.gs` と `Sample.gs` も忘れずに）
4. スプレッドシートを開き直すと、メニューに「議事録」が出る

### 2. 最初の設定をする

1. 「議事録」→「設定」→「最初の設定」を選ぶ
2. 権限の許可を求められる。「このアプリは Google で確認されていません」と出たら、「詳細」→「（プロジェクト名）に移動」で進む（自分で作ったプログラムなので問題ない）。許可する権限は [SECURITY.md](SECURITY.md) の「権限」のとおり
3. マイドライブに「議事録の下書き（meeting-tasks）」と「議事録（meeting-tasks・開発用）」のフォルダができ、「会議」「TODO」「設定」「記録」のシートができる

### 3. Gemini の API キーを入れる（開発用）

1. [Google AI Studio](https://aistudio.google.com/) に会社のアカウントでログインし、「Get API key」→「API キーを作成」でキーを作る（会社の管理者が AI Studio を止めている場合は、個人の Google アカウントで作る）
2. 「議事録」→「設定」→「Gemini（AI Studio）の API キーを入れる」で貼る。キーはあなただけが読める場所（ユーザー プロパティ）に保存され、シートには書かれない

AI Studio の無料のキーは、送った内容が Google のサービス改善に使われることがあります。そのため、設定シートの「AI の呼び方」が AI Studio のあいだは、**架空のサンプルの会議メモしか送れない**ようにしてあります。

### 4. 試す

1. 「議事録」→「サンプルの会議メモで試す」。1〜2 分で「【お試し】2026-11-05_サンプル定例」の下書きができる
2. 下書きを開いて読み、直したいところを直す。「TODO」シートで担当者・期限・登録先（☑）を直す
3. 「議事録」→「確認して承認する…」→「承認する」。設定シートの「お試し実行」が「する」のあいだは、保存・登録はせず、登録する予定の内容だけを表示する

Backlog とカレンダーへの登録まで試すときは、次のようにします（サンプルの内容は架空なので、**テスト用の Backlog プロジェクト**を使ってください）。

1. 設定シートに Backlog のスペース（例：`xxx.backlog.jp`）とテスト用のプロジェクトキーを書く
2. 「議事録」→「設定」→「Backlog の API キーを入れる」（Backlog の「個人設定」→「API」で発行）
3. 設定シートの「お試し実行」を「しない」にしてから、もう一度サンプルで下書きを作り、承認する

## 本物の会議で使う（会社の準備ができてから）

1. **Vertex AI にする**：会社の Google Cloud プロジェクトで Vertex AI を使えるようにしてもらい、[SECURITY.md](SECURITY.md) の「ゼロデータ保持」の設定をしてもらう。そのうえで次を行う
   - `appsscript.json` の `oauthScopes` に `https://www.googleapis.com/auth/cloud-platform` を足す
   - Apps Script の「プロジェクトの設定」で、Google Cloud プロジェクトを会社のプロジェクトに変える
   - 設定シートの「AI の呼び方」を「Vertex AI」にし、「Vertex AI のプロジェクト ID」を書く
2. **保存先を共有ドライブにする**：まだできません（下の「まだできていないこと」）
3. **自動で下書きを作る**（任意）：設定シートの「自動で下書きを作る会議名」に、対象の会議名に含まれる言葉（例：`定例`）を書き、「議事録」→「設定」→「自動で下書きを作る：オンにする」。15 分ごとに探し、下書きができたらメールで知らせる

## 設定シートの項目

| 項目 | 内容 |
|---|---|
| AI の呼び方 | 「AI Studio（開発用・サンプルだけ）」か「Vertex AI」 |
| Gemini のモデル | 初期値は `gemini-flash-latest`（いちばん新しい Flash を指す別名）。止まるときや提供が終わったときに変える |
| Vertex AI のプロジェクト ID・場所 | Vertex AI のときだけ。場所の初期値は `asia-northeast1`（東京） |
| 議事録の保存先フォルダ・下書きフォルダ | 最初の設定で作ったフォルダ |
| 社内のドメイン | カレンダーの招待と、保存先の共有の確認に使う。最初の設定で自分のアドレスのドメインが入る |
| Backlog のスペース・プロジェクトキー | 空なら Backlog には登録せず、手で登録する一覧を出す |
| お試し実行 | 「する」のあいだは、承認しても保存・登録しない |
| 自動で下書きを作る会議名 | この言葉を名前に含む会議メモだけを自動で処理する。空なら自動では作らない |
| 使った記録を残す | テスト用。「する」にすると「記録」シートに 1 回ずつ残す（会議名と数だけ。中身は残さない） |

## ファイル構成

| ファイル | 内容 |
|---|---|
| `src/appsscript.json` | タイムゾーン（東京）と、使う権限の一覧。ドライブ・ドキュメント・カレンダーの API を使えるようにする設定（「拡張サービス」。これがないと「Google Drive API has not been used in project … or it is disabled」で止まる） |
| `src/Menu.gs` | メニュー・最初の設定・API キー・自動で作る設定 |
| `src/Settings.gs` | 管理シートと設定の読み書き |
| `src/Layout.gs` | 管理シートの見た目（状態の色・直せる列の色・隠す列・列の幅）。「最初の設定」のたびにかけ直す |
| `src/Draft.gs` | 会議メモ → 下書き（いまの版の Step 1〜7） |
| `src/Approve.gs` | 確認画面・承認・保存・登録（Step 8〜13） |
| `src/Gemini.gs` | Gemini（AI Studio・Vertex AI） |
| `src/Backlog.gs` | Backlog の API |
| `src/Google.gs` | Google ドライブ・ドキュメント・カレンダーの API |
| `src/Markdown.gs` | 下書きと確定版の Markdown を作る・書き直す |
| `src/Log.gs` | 使った記録と集計（テスト用） |
| `src/Util.gs` | ファイル名・日付・名前の照合・登録先の判定・共有の範囲の確認など |
| `src/Prompt.gs`・`src/Sample.gs` | **自動で作るファイル**。`minutes-template.md` と `samples/sample-meeting-memo.md` から作る |
| `src/Pick.html`・`src/Confirm.html` | 会議メモを選ぶ画面・確認画面 |
| `tools/build.mjs` | `Prompt.gs`・`Sample.gs` を作り直す |
| `test/run.mjs` | パソコンで動くテスト |

## 直すとき

- 議事録の書き方を変えるときは、`skills/meeting-tasks/references/minutes-template.md` を直してから `node gas/tools/build.mjs` を実行する（Claude 版と Apps Script 版が同じ書き方になる）
- 直したら `node gas/test/run.mjs` を実行する。にせものの Google を使って、下書き → 承認 → 登録の流れまで確かめる（`Prompt.gs` が古いままでも失敗する）
- `src/Util.gs` の `APP_VERSION` を上げる。版は確定版の議事録の最後と、メニュー「この版について」に出る

## 実際の環境で試す項目

パソコンのテストは、Google の API の形をまねたにせもので動かしています。次は本物の Google の環境で確かめてください。

| # | 確かめること | 結果 |
|---|---|---|
| 1 | 最初の設定で、権限の画面に [SECURITY.md](SECURITY.md) の権限だけが出る。フォルダ 2 つとシート 4 つができる | |
| 2 | サンプルで試すと、下書きのドキュメントができ、見出し・表・箇条書きが Google ドキュメントの形になっている（Markdown の取り込み） | |
| 3 | 下書きを直してから承認すると、直した内容が確定版に残り、確認用のメモが消え、TODO の表がシートの内容になる（Markdown の書き出し） | |
| 4 | 要確認事項を残したまま承認すると、「決まっていないこと」に（要確認）付きで入る | |
| 5 | 下書きがゴミ箱に移る | |
| 6 | 「お試し実行」が「する」のとき、保存先にも Backlog・カレンダーにも何もできない | |
| 7 | テスト用の Backlog プロジェクトに、担当者・期限・種別「タスク」・優先度「中」で課題ができる。似た課題がある TODO に「⚠ 似た課題あり」が出る | |
| 8 | カレンダーに、期限日の終日・非公開の予定ができ、前日 9:00 に通知が来る。社外のアドレスは招待されない | |
| 9 | 保存先フォルダを「リンクを知っている全員」に共有すると、確認画面で承認できなくなる | |
| 10 | 承認の途中で止めて（例：Backlog の API キーを一時的に消す）、直してから承認し直すと、続きから登録され、二重にならない | |
| 11 | AI Studio の設定のまま「議事録を作る」を開くと、本物の会議メモは選べない | |
| 12 | Vertex AI の設定で、本物の会議メモ（タブが「メモ」「文字起こし」に分かれたもの）から下書きができる | |
| 13 | 1 時間くらいの会議でも、6 分の上限までに下書きができる | |
| 14 | 自動で作る設定で、決めた会議名の新しいメモだけが処理され、メールが届く | |

## まだできていないこと

- **共有ドライブの保存先を選ぶ画面**：書き込みの権限を「このツールが作ったファイル・フォルダだけ」に絞っているため、いまはこのツールが作ったフォルダにしか保存できない。共有ドライブのフォルダを選べるように、フォルダを選ぶ画面（Google Picker）を足す
- **Vertex AI での動作確認**：コードはあるが、まだ本物の Google Cloud で動かしていない
- **社内限定のアドオンにする**：全社で使うときの配り方（設計図の「試用から全社へ」）
- **実際の環境で試す項目**：上の表をすべて確かめる
