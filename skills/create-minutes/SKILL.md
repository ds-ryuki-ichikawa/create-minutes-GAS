# 議事録作成

Claude Code では `/create-minutes` と入力すると実行する。Claude Desktop の Cowork では、`/` で出るメニューから `create-minutes` を選ぶか、会議メモの URL を貼って議事録の作成を頼むと実行する。  
Google Docs の会議メモを読み込み、指定フォーマットで議事録・TODO を生成し、ローカル保存・Backlog 課題登録・Google カレンダーへのリマインド登録・Slack 予約送信・Canvas 登録を自動で行う。

引数: `$ARGUMENTS`

---

## 引数一覧

| 引数 | 必須 | 説明 |
|------|:----:|------|
| `--doc-id` | ✓ | 会議メモ（Gemini によるメモ）の Google Docs ドキュメント ID または URL |
| `--slack-channel` | — | 送信先チャンネル名（例: `ms部`, `#01_ﾏｰｹﾃｨﾝｸﾞｿﾘｭｰｼｮﾝ部`）または チャンネル ID。省略時は Slack への共有（Canvas 作成・送信）を行わない |
| `--mention-users` | — | メンション対象のユーザー表示名（例: `西川,松下`）または ユーザー ID。カンマ区切り。省略時はメンションしない |
| `--send-at` | — | 送信予約日時。柔軟な表現を受け付ける（後述）。`--slack-channel` を指定したときは必須 |
| `--canvas-id` | — | 更新対象の Slack Canvas ID。省略時は新規作成 |
| `--backlog-project` | — | TODO を課題登録する Backlog プロジェクトキー。省略時は `IB_TASK` |
| `--prev` | — | 前回の議事録。ローカルのファイルパス（`~/Documents/minutes/` 内ならファイル名だけでも可）または Google Docs の ID・URL。省略時は同じ名前の会議の議事録を自動で探す。`--prev none` で前回との比較をしない |
| `--dry-run` | — | お試し実行。保存・Backlog 登録・カレンダー登録・Canvas・Slack 送信は行わず、実行予定の内容を表示するだけにする |

**`--send-at` に指定できる表現の例:**

| 入力例 | 解釈 |
|--------|------|
| `明日9時` / `明朝9時` | 翌日 09:00 JST |
| `今日18時` / `今夜18時` | 当日 18:00 JST |
| `15日9時` | 当月 15日 09:00 JST |
| `5/15 9:00` | 5月15日 09:00 JST |
| `2026-05-15 09:00` | 指定日時 JST（秒省略可） |
| `30分後` / `1時間後` | 現在時刻から相対指定 |
| `9:00` / `09:00` | 当日 09:00 JST（過去なら翌日） |

分・秒を省略した場合は `:00` とみなす。すべて JST で解釈する。

## 環境による違い

Claude Code（VS Code・ターミナル）と Claude Desktop の Cowork のどちらでも動くように書いている。違いは次の 3 点。

- **ツール名**: 手順に書いたツール名（`mcp__claude_ai_Google_Drive__read_file_content` など）は Claude Code での例。Cowork などでは名前が違うことがあるので、使えるツールの中から同じ機能のもの（Google ドライブのファイル読み込み、Backlog の課題検索・登録、Google カレンダーの予定一覧・作成など）を選んで使う。引数名は各ツールの定義に合わせる
- **保存先フォルダ**: 議事録は `~/Documents/minutes/` に保存する（以下 `MINUTES_DIR`）。Cowork では、接続されたフォルダのうち `minutes` フォルダ（またはドキュメントフォルダの中の `minutes`）を `MINUTES_DIR` とする。読み書きできるフォルダがない場合は、ユーザーに「ドキュメントの minutes フォルダを接続してください」と伝えてから進める。接続されなければ、議事録を Cowork の成果物ファイルとして出力し、その場所を保存先として報告する。claude.ai のチャットや Web 版 Claude Code（claude.ai/code）のようにクラウドで動く環境では、`~/Documents/minutes/` に書いてもユーザーのパソコンには保存されない。この場合は「パソコンには保存されません」とはっきり伝え、議事録をダウンロードできるファイルとして出す（出せなければ本文をコピーできる形で表示する）。お試し実行の保存予定の表示でも同じように伝える
- **Backlog**: Backlog のツールが使えない場合も処理を止めず、Step 9 の「Backlog が使えない場合」に従う

## 実行手順

### Step 1: 引数をパースする

引数（`$ARGUMENTS`）から以下を抽出し、各変数に格納する。引数が空の場合は、ユーザーのメッセージから読み取る（会議メモの URL だけが書かれていれば `--doc-id`、「お試し」とあれば `--dry-run` とみなす）。`--doc-id` がわからなければユーザーに聞く:

- `DOC_ID` ← `--doc-id` の値（URL の場合は `/document/d/{ID}/` の `{ID}` 部分を抽出する）
- `RAW_CHANNEL` ← `--slack-channel` の値（名前または ID の文字列そのまま）
- `RAW_USERS` ← `--mention-users` の値をカンマで分割した配列
- `RAW_SEND_AT` ← `--send-at` の値（自然言語または日付文字列）
- `CANVAS_ID` ← `--canvas-id` の値（省略時は空文字）
- `BACKLOG_PROJECT` ← `--backlog-project` の値（省略時は `IB_TASK`）
- `DRY_RUN` ← `--dry-run` が指定されていれば true、なければ false
- `SLACK_ENABLED` ← `--slack-channel` が指定されていれば true、なければ false
- `PREV_SOURCE` ← `--prev` の値（省略時は空文字＝自動で探す。`none` なら前回との比較をしない）

**`SLACK_ENABLED` が false の場合:**  
Slack への共有は行わない。Step 2・Step 11・Step 12 は実行せず、Step 13 の Canvas・Slack の行は「—（`--slack-channel` 指定なし）」とする。  
`--slack-channel` があって `--send-at` がない場合は、送信日時をユーザーに確認してから進める。

**`DRY_RUN` が true の場合:**  
Step 8 以降は外部・ファイルへの書き込みを一切行わず、各ステップで「実行予定の内容」を表示するだけにする。表示の先頭には `🧪 お試し実行（実際には保存・登録・送信しません）` と出す。  
Step 2 で Slack のツールが使えない場合も中断せず、チャンネル名・ユーザー名をそのまま表示に使う。

**`--send-at` の日時解釈:**  
`RAW_SEND_AT` を現在日時（JST）を基準に解釈し、`SEND_AT_TS`（Unix タイムスタンプ、秒）に変換する。  
解釈結果を `SEND_AT_LABEL`（例: `2026-05-15 09:00 JST`）にも格納する。

### Step 2: Slack チャンネルとユーザーを名前で解決する

`SLACK_ENABLED` が false の場合はこのステップを飛ばす。

**使う Slack ツール:**  
Slack のツール名は接続方法によって異なる（例: `mcp__slack__slack_search_channels`。claude.ai の Slack コネクタなら `mcp__claude_ai_Slack__` で始まる名前）。Step 2・11・12 の手順は機能で書いているので、使える Slack ツールの中から同じ機能のもの（チャンネル検索・ユーザー検索・Canvas 作成・Canvas 更新・予約送信・下書き作成）を選んで使う。引数名は各ツールの定義に合わせる。どれも見つからない場合は「Slack が使えない場合」として扱う。

**Slack が使えない場合:**  
Slack のツールが使えない（コネクタ未接続・未認可）場合は処理を中断せず、`SLACK_AVAILABLE` を false にする。  
このとき `CHANNEL_ID` は使わず、`MENTIONS` は `RAW_USERS` の各名前を `@名前` の形でスペース区切りにしたものとする。以降 Step 11・Step 12 は「Slack が使えない場合」の手順に従う。  
Slack のツールが使える場合は `SLACK_AVAILABLE` を true にし、以下の手順で解決する。

**チャンネル解決:**  
`RAW_CHANNEL` が `C` で始まる英数字のみの文字列（例: `C07SQKSG1QW`）であれば ID として `CHANNEL_ID` に格納する。  
そうでなければチャンネル検索のツールで検索し、最も名前が近いチャンネルの ID を `CHANNEL_ID` に格納する。  
検索結果が複数ある場合はユーザーに候補を提示して選択を求める。

**ユーザー解決:**  
`RAW_USERS` の各要素について:
- `U` で始まる英数字のみの文字列であれば ID として使用する
- そうでなければユーザー検索のツールで名前検索し、最も近い 1 件の ID を使用する
- 候補が複数ある場合はユーザーに提示して確認する

全ユーザー ID を `<@UXXX>` 形式に変換してスペース区切りで結合し、`MENTIONS` に格納する（例: `<@U010P67LCBV> <@UKWH3GRA4>`）。`--mention-users` が省略された場合、`MENTIONS` は空にする。

### Step 3: 元ドキュメントを読み込む

Google ドライブのファイル読み込みツール（例: `mcp__claude_ai_Google_Drive__read_file_content`）の `fileId` に `DOC_ID` を渡してドキュメントを読み込む。  
ドキュメントのタイトルと本文全体を取得し、タイトルを `DOC_TITLE` に格納する。

- 本文には「メモ」タブ（概要・決定事項・次のステップ・詳細）と「文字起こし」タブの両方が含まれる
- ファイルが見つからない・権限がない場合は処理を中断し、ドキュメントの共有設定を確認するようユーザーに伝える
- Google ドライブのツールが使えない場合は処理を中断し、Google ドライブのコネクタを接続するようユーザーに伝える

### Step 4: 変換プロンプトを読み込む

このスキルのフォルダにある `references/minutes-template.md`（`${CLAUDE_SKILL_DIR}/references/minutes-template.md`）を読み込む。  
ファイルが見つからない場合は処理を中断し、スキルのファイル一式（`references/` フォルダを含む）がそろっているか確認するようユーザーに伝える。  
このファイルは議事録の生成方法を記述した変換プロンプトであり、Step 5 でそのまま指示として使用する。

### Step 4-2: 前回の議事録を読み込む

同じ会議の前回の議事録を読み込み、今回の議事録で「前回からの変更」を書けるようにする。`PREV_SOURCE` が `none` の場合はこのステップを飛ばし、`PREV_MINUTES` を空にする。

**1. 前回の議事録を見つける**

- `PREV_SOURCE` が Google Docs の ID・URL の場合: Step 3 と同じ Google ドライブのツールで読み込む
- `PREV_SOURCE` がファイルパスの場合: そのファイルを読み込む。ファイル名だけなら `MINUTES_DIR` から探す
- `PREV_SOURCE` が空の場合（自動で探す）:
  - `DOC_TITLE` から Step 8 と同じ手順で `sanitized_title` を作る
  - `MINUTES_DIR` から `{YYYY-MM-DD}_{sanitized_title}.md`（末尾に `_2`、`_3` … が付いたものも含む）を探し、日付が今回の会議日より前のものの中で最も新しいものを選ぶ（同じ日付が複数あれば末尾の番号が大きいもの）
- 見つからない・読み込めない場合は処理を止めずに `PREV_MINUTES` を空にし、「前回の議事録は見つかりませんでした（初回の会議として扱います）」と表示する
- 見つかった場合は、本文を `PREV_MINUTES`、ファイルの場所を `PREV_FILE`、前回の開催日を `PREV_DATE` に格納し、「📎 前回の議事録：{PREV_FILE}（{PREV_DATE}）と比べます」と表示する

**2. 前回の TODO の Backlog の状態を調べる**

`PREV_MINUTES` が空でない場合、前回の TODO を登録した Backlog の課題を探す。

- Backlog の課題検索ツール（例: `mcp__backlog__get_issues`）で、`keyword` に前回の会議名（`PREV_MINUTES` のタイトル行から「 議事録」を除いたもの）、`count` に 20 を指定して検索する
- 説明文に `開催日: {PREV_DATE}` を含む課題だけを、前回の TODO の課題とみなす
- 課題キー・件名・状態を `PREV_BACKLOG` に格納する。見つからなければ空にする（前回 Backlog に登録していない場合もある）
- Backlog のツールが使えない場合は `PREV_BACKLOG` を空にして先に進む（前回の TODO の状況は会議での発言だけで判断する）

### Step 5: 議事録を Markdown で生成する

Step 3 で取得した元ドキュメントの本文を入力として、Step 4 で読み込んだ変換プロンプトの指示に従って議事録を Markdown で生成する。`PREV_MINUTES` が空でない場合は、`PREV_MINUTES` と `PREV_BACKLOG` も「前回の議事録」「前回の TODO の Backlog の状態」として渡す。

変換プロンプトに記載のない点については以下のデフォルトルールを適用する:
- 箇条書きを積極活用し、読みやすく簡潔にまとめる
- 会議日時・参加者は変換プロンプトの「会議情報」に記載するため、ここでは重複して書かない
- 議事録の冒頭に以下のタイトル行を挿入する（`DOC_TITLE` 末尾の「 - Gemini によるメモ」は除く）:

```
# {DOC_TITLE} 議事録

**作成日**: {今日の日付 YYYY-MM-DD}
```

生成した議事録全文を `MINUTES_MD` に格納する。

### Step 6: 内容をチェックし、人が修正する

`MINUTES_MD` から以下を抽出し、チェックリストとして表示する:

```
📋 議事録の内容を確認してください

■ 担当者・期限
  {TODO を「{番号}. [{区分}] {内容}｜{担当者}｜{期限}」の形で番号付きで列挙。担当者または期限が「未定」、区分が「不明」の項目には ⚠ を付ける}

■ 非公開情報（社外に共有する前に伏せるか確認）
  {「非公開情報」セクションの内容}

■ 前回からの変更（前回：{PREV_DATE}｜{PREV_FILE}）
  {「前回からの変更」セクションの内容。前回の議事録がない場合は「前回の議事録なし（初回として扱いました）」}

■ 要確認事項
  {「要確認事項」セクションの内容}

修正内容をチャットで送ってください。問題なければ「OK」と送ってください。
```

- チェックリストを表示したら処理を止め、ユーザーの返答を待つ
- 修正指示を受けたら `MINUTES_MD` に反映し、変更点（変更前 → 変更後）を表示してから、再度チェックリストを表示する
- 反映して解消した要確認事項は「要確認事項」セクションから削除する
- ユーザーが「OK」と返答するまで繰り返す。OK を受けるまで Step 7 以降（保存・Slack 送信など）は実行しない
- 「OK」を受けた時点で要確認事項が残っている場合は、「要確認事項が {件数} 件残っていますが、このまま議事録に載せて進めますか？」と 1 回だけ確認する。再度 OK なら Step 7 へ進み、修正指示ならチェックを続ける

### Step 7: TODO を抽出する

`MINUTES_MD` の「TODO」セクションの内容を、Slack 通知・Backlog 登録で使うために以下の Markdown テーブルに整形する。  
`TODO_MD` は議事録本文（保存・Canvas）には追加しない（`MINUTES_MD` に TODO が既に含まれるため）:

```markdown
## TODO一覧

| 対応フラグ | 対応内容 | 区分 | 担当者 | 期限 |
|-----------|---------|------|--------|------|
| [ ] | {内容} | {社内・社外・不明} | {担当者名または「未定」} | {期限（YYYY-MM-DD）または「未定」} |
```

- 担当者名はドキュメント本文から判断する（記載がなければ「未定」）
- 区分は `MINUTES_MD` の「TODO」セクションの区分をそのまま使う
- 期限は `YYYY-MM-DD` 形式。「次回MTGまで」「月末」など相対表現は可能な範囲で日付化する
- TODO が 0 件の場合は「*TODOなし*」と記載する

抽出した Markdown テーブルを `TODO_MD` に、件数を `TODO_COUNT` に格納する。

### Step 8: ローカルに保存する

Step 6 のチェックで OK を受けた確定版を保存する。保存先は実行ディレクトリに関係なく `MINUTES_DIR`（「環境による違い」を参照）に固定する。

1. `MINUTES_DIR` が存在しない場合は作成する（例: PowerShell なら `New-Item -ItemType Directory -Force "$env:USERPROFILE\Documents\minutes"`、bash なら `mkdir -p ~/Documents/minutes`）
2. ファイル名: `{YYYY-MM-DD}_{sanitized_title}.md`（`YYYY-MM-DD` は会議日付）。日付はファイル名の先頭に 1 回だけ付ける。`sanitized_title` は `DOC_TITLE` から以下の順に作る:
   - 末尾の「 - Gemini によるメモ」を除く
   - 日付（例: `2026/10/02`、`2026-10-02`、`20261002`、`10/2`）、時刻（例: `14:29`）、タイムゾーン（例: `JST`）を除く
   - 空白・記号をアンダースコアに置換し、連続・先頭・末尾のアンダースコアを整理する
   - 結果が空になった場合は「会議」とする
   - 例: `MTG - 2026/10/02 14:29 JST - Gemini によるメモ` → `2026-10-02_MTG.md`
3. 同名ファイルが既に存在する場合は上書きせず、末尾に `_2`、`_3` …を付けて空いている名前で保存する
4. `MINUTES_MD`（議事録本文）をファイルに保存する
5. 保存先の絶対パスを `LOCAL_FILE_PATH` に格納する

### Step 9: Backlog に課題を登録する

`TODO_MD` のうち区分が「社内」の行を、`BACKLOG_PROJECT` の課題として登録する。社内の TODO が 0 件の場合はこのステップを飛ばす。

- 区分が「社外」の行（お客様・取引先の作業）は社内の Backlog に登録しない。確認一覧に「登録しない TODO」として表示する
- 区分が「不明」の行は ⚠ を付けて確認一覧に出し、登録するかどうかをユーザーに決めてもらう
- 「（前回から継続）」の行で、`PREV_BACKLOG` に対応する課題がある場合は新しく登録しない。確認一覧に「前回の課題を継続：{課題キー}（{状態}）」と表示し、期限が変わった場合は課題の期限の更新を提案する（更新はユーザーが指示したときだけ行う）

**Backlog が使えない場合:**  
Backlog のツールが使えない（コネクタ未接続・未認可）場合は処理を中断せず、`BACKLOG_AVAILABLE` を false にする。課題は作らず、Step 13 で「未登録：手動登録用の一覧を表示済み」と報告し、以下の一覧を表示する（担当者の照合と似た課題の確認はしない）:

```
📝 Backlog が接続されていないため、以下を {BACKLOG_PROJECT} に手動で登録してください

  1. {件名}｜担当：{担当者}｜期限：{期限 または なし}
  ...

  登録しない TODO（社外の作業）：
  - {内容}｜{担当者}｜{期限}
```

**1. 登録内容を組み立てる**

- プロジェクト・ユーザー・種別・優先度は、Backlog のプロジェクト・プロジェクトユーザー・種別・優先度の取得ツール（例: `mcp__backlog__get_project`、`mcp__backlog__get_project_users`、`mcp__backlog__get_issue_types`、`mcp__backlog__get_priorities`）で取得する
- 件名: TODO の「対応内容」
- 種別: 「タスク」、優先度: 「中」
- 担当者: TODO の担当者名とプロジェクトユーザーの `name` を、半角・全角スペースを無視して照合する
  - 1 人に一致 → その人を担当者にする
  - 一致なし、または名字だけで複数人に一致 → 担当者は空にし、⚠ を付けて確認対象にする
- 期限: TODO の期限（`YYYY-MM-DD`）。「未定」なら設定しない
- 重複確認: TODO の内容から主な語句（例: 「注文メール」「取り込み」）を選び、Backlog の課題検索ツール（例: `mcp__backlog__get_issues`）の `keyword` で `BACKLOG_PROJECT` の課題を検索する。完了済みも含めて、同じ作業と思われる課題があれば、その課題キー・件名・状態を控えて確認対象にする。検索結果には課題の説明文がまるごと含まれて量が多くなるため、語句は TODO 全体で 3〜4 個までに絞り（1 つの語句で複数の TODO をまとめて確かめる）、`count` は 10 にする
- 詳細: 以下の形式

```
会議: {DOC_TITLE（「 - Gemini によるメモ」を除く）}
開催日: {会議日付}
元メモ: https://docs.google.com/document/d/{DOC_ID}/edit
（/create-minutes により自動登録）
```

**2. 登録前に確認する**

以下を表示し、処理を止めてユーザーの返答を待つ:

```
📝 Backlog（{BACKLOG_PROJECT}）に以下の {件数} 件を登録します

  1. {件名}｜担当：{担当者 または ⚠未設定}｜期限：{期限 または なし}
     {似た課題がある場合: ⚠ 似た課題あり：{課題キー}「{件名}」（{状態}）}
  ...

  登録しない TODO（社外の作業）：
  - {内容}｜{担当者}｜{期限}
  {区分が「不明」の行がある場合: ⚠ 区分が不明：{内容}（社内の作業なら登録します）}

担当者の指定・除外する課題があればチャットで送ってください。問題なければ「登録」と送ってください。
```

- 似た課題がある TODO は、登録すると重複するおそれがあることを一言添える（特に完了済みの課題と重なる場合）

- 修正指示を受けたら反映して再表示する
- 「登録」を受けるまで課題は作成しない
- `DRY_RUN` が true の場合は一覧を表示するだけで、確認は求めずに次のステップへ進む

**3. 登録する**

Backlog の課題登録ツール（例: `mcp__backlog__add_issue`）で 1 件ずつ登録する。作成された課題キーと URL（`https://{スペースキー}.backlog.jp/view/{課題キー}`。スペースキーはスペース情報の取得ツール（例: `mcp__backlog__get_space`）で取得する）を `BACKLOG_ISSUES` に、件数を `BACKLOG_COUNT` に格納する。  
途中で失敗した場合は、そこで止めて登録済みの課題キーと失敗した TODO をユーザーに伝える。  
登録した課題は権限によっては削除できないため、不要になった課題はコメントを付けてクローズするか、管理者に削除を依頼するようユーザーに伝える。

### Step 10: Google カレンダーにリマインドを登録する

`TODO_MD` のうち区分が「社内」で期限が決まっている行（Step 9 で登録対象にした行）について、実行者の Google カレンダーにリマインドの予定を作る。期限が「未定」の TODO と社外の TODO は対象外（社外の期限もリマインドしたい場合は、確認時にユーザーが追加を指示する）。対象が 0 件の場合はこのステップを飛ばす。

**Google Calendar が使えない場合:**  
Google Calendar のツールが使えない（コネクタ未接続・未認可）場合は処理を中断せず、`CALENDAR_AVAILABLE` を false にする。予定は作らず、Step 13 で「未登録：手動登録用の一覧を表示済み」と報告し、以下の一覧を表示する:

```
📅 Google Calendar が接続されていないため、以下を手動でカレンダーに登録してください

  1. {期限}（終日）【期限】{対応内容}｜担当：{担当者}
  ...
```

**1. 予定の内容を組み立てる**

- 予定の種類: 期限日の終日予定（終了日は期限日の翌日を指定する）
- タイトル: `【期限】{対応内容}`
- 通知: ポップアップ通知を開始の 900 分前に設定する（期限の前日 9:00 JST に鳴る）
- 説明: 以下の形式

```
担当者: {担当者名または「未定」}
会議: {DOC_TITLE（「 - Gemini によるメモ」を除く）}
Backlog: {Step 9 で登録した課題の URL。登録していなければ省く}
元メモ: https://docs.google.com/document/d/{DOC_ID}/edit
（/create-minutes により自動登録）
```

- 招待: TODO の担当者を、メールアドレスがわかる場合だけ招待する
  - Backlog では他のユーザーのメールアドレスを取得できない（本人のものしか見えない）ため、担当者のメールアドレスは確認時にユーザーから受け取る
  - 担当者が実行者本人の場合は招待しない。本人かどうかは、予定を作るカレンダーの持ち主（自分）のメールアドレスと比べて判断する。会議の招待者情報などから担当者のアドレスがわかっても、それが自分のアドレスなら招待しない
  - メールアドレスがわからない担当者は招待せず、⚠ を付けて確認対象にする
- 重複防止: Google カレンダーの予定一覧ツール（例: `mcp__claude_ai_Google_Calendar__list_events`）で期限日（`startTime`: 期限日 `T00:00:00`、`endTime`: 翌日 `T00:00:00`、`fullText`: `【期限】`）の予定を取得し、同じタイトルの予定がすでにある場合は作らず、「登録済み」として扱う

**2. 登録前に確認する**

以下を表示し、処理を止めてユーザーの返答を待つ:

```
📅 Google カレンダーに以下の {件数} 件のリマインドを登録します（期限日の終日予定・前日 9:00 に通知）

  1. {期限}【期限】{対応内容}｜招待：{メールアドレス または ⚠なし（{担当者名}）}
  ...

招待する人のメールアドレス・除外する予定があればチャットで送ってください。問題なければ「登録」と送ってください。
```

- 修正指示を受けたら反映して再表示する
- 「登録」を受けるまで予定は作成しない
- `DRY_RUN` が true の場合は一覧を表示するだけで、確認は求めずに次のステップへ進む

**3. 登録する**

Google カレンダーの予定作成ツール（例: `mcp__claude_ai_Google_Calendar__create_event`）で 1 件ずつ登録し、件数を `CALENDAR_COUNT` に格納する。以下は Claude Code のツールの引数名で、ほかの環境では各ツールの定義に合わせる:
- `summary`: タイトル
- `allDay`: true
- `startTime`: 期限日 `T00:00:00`（例: `2026-10-30T00:00:00`）、`endTime`: 翌日 `T00:00:00`
- `overrideReminders`: `[{"method": "popup", "minutes": 900}]`
- `availability`: `AVAILABILITY_FREE`（リマインドなので、予定の空き状況をふさがない）
- `description`: 説明
- `attendees`: 招待する人の `email`（いなければ省く）


途中で失敗した場合は、そこで止めて登録済みの予定と失敗した TODO をユーザーに伝える。

### Step 11: Slack Canvas を作成または更新する

`SLACK_ENABLED` が false の場合はこのステップを飛ばす。

Canvas に書き込むコンテンツ（`CANVAS_CONTENT`）は `MINUTES_MD` をそのまま使う。

**Slack が使えない場合（`SLACK_AVAILABLE` が false）:**  
Canvas は作成しない。`CANVAS_URL` は空にし、Step 12 のメッセージでは Canvas の案内の代わりに「議事録ファイルは別途共有します」と記載する。

**`CANVAS_ID` が空の場合（新規作成）:**

Canvas 作成のツール（例: `mcp__slack__slack_create_canvas`）で新規 Canvas を作成する:
- `channel_id`: `CHANNEL_ID`
- `title`: `{DOC_TITLE} 議事録`
- `document_content`: `CANVAS_CONTENT`

作成された Canvas の URL を `CANVAS_URL` に格納する。

**`CANVAS_ID` が指定されている場合（上書き更新）:**

Canvas 更新のツール（例: `mcp__slack__slack_update_canvas`）で既存 Canvas を更新する:
- `canvas_id`: `CANVAS_ID`
- `document_content`: `CANVAS_CONTENT`

Canvas URL は `https://app.slack.com/canvas/{CANVAS_ID}` として `CANVAS_URL` に格納する。

### Step 12: Slack へ予約送信する

`SLACK_ENABLED` が false の場合はこのステップを飛ばす。

以下の形式で `MESSAGE_TEXT` を構成する:

```
{MENTIONS}

📋 *{DOC_TITLE} 議事録* を共有します。

────────────────────
▼ 決定事項・要約
{MINUTES_MD の「決定事項」または「まとめ」セクションの内容を 3〜5 行に要約}

▼ TODO（{TODO_COUNT} 件）
{TODO_MD の各行を「・{対応内容}｜{担当者}｜{期限}」の箇条書きに変換して列挙。社外の TODO は先頭に「［社外］」を付ける（Slack は Markdown の表を表示できないため）}

▼ Backlog 課題（{BACKLOG_COUNT} 件）
{BACKLOG_ISSUES の課題キーと URL を 1 行ずつ列挙。登録していない場合はこのブロックを省く}
────────────────────

詳細議事録・TODO 管理は Canvas をご確認ください 👇
{CANVAS_URL}
```

- `MENTIONS` が空の場合は、先頭のメンション行と続く空行を省く
- `MESSAGE_TEXT` には `MINUTES_MD` の「非公開情報」セクションに挙げた内容（金額・顧客名・個人情報・社内事情など）を含めない。要約・TODO の文言に含まれる場合は伏せるか一般的な表現に言い換える

予約送信のツール（例: `mcp__slack__slack_schedule_message`）で予約送信する:
- `channel_id`: `CHANNEL_ID`
- `text`: `MESSAGE_TEXT`
- `post_at`: `SEND_AT_TS`（Unix タイムスタンプ）

> **注意**: 即時送信のツール（例: `mcp__slack__slack_send_message`）は使用しない（「Sent using Claude」フッターが付くため）。  
> `SEND_AT_TS` が現在時刻より過去の場合は、下書き作成のツール（例: `mcp__slack__slack_send_message_draft`）を代わりに使用する。

**Slack が使えない場合（`SLACK_AVAILABLE` が false）:**  
送信は行わず、以下のように `MESSAGE_TEXT` をコピーしやすい形で表示する:

````
💬 Slack が接続されていないため、以下のメッセージを #{RAW_CHANNEL} に手動で投稿してください（予定日時: {SEND_AT_LABEL}）

```
{MESSAGE_TEXT}
```

※ あわせて議事録ファイル（{LOCAL_FILE_PATH}）を添付してください
````

### Step 13: 完了報告

以下をまとめて出力する:

```
✅ 議事録作成完了

📄 ローカル保存先 : {LOCAL_FILE_PATH}（クラウドで動く環境では「パソコンには未保存：ダウンロード用のファイルを表示済み」）
📝 Backlog 課題   : {BACKLOG_COUNT} 件登録（{課題キーをカンマ区切り}）（Backlog が使えない場合は「未登録：手動登録用の一覧を表示済み」）
📅 カレンダー     : {CALENDAR_COUNT} 件のリマインドを登録（Google Calendar が使えない場合は「未登録：手動登録用の一覧を表示済み」）
🎨 Canvas URL    : {CANVAS_URL}（`--slack-channel` 指定なしの場合は「—」）
💬 Slack 予約送信 : {SEND_AT_LABEL} にチャンネル #{チャンネル名} へ送信予定（Slack が使えない場合は「未送信：手動投稿用のメッセージを表示済み」、`--slack-channel` 指定なしの場合は「—」）
✅ TODO           : {TODO_COUNT} 件抽出（社内 {社内の件数} 件・社外 {社外の件数} 件・不明 {不明の件数} 件。不明が 0 件なら「・不明」以降は省く）
🔗 前回の議事録   : {PREV_FILE}（{PREV_DATE}）と比較（前回の議事録がない場合は「なし」）
```
